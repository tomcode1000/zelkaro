Five moves, one source of truth

Every verdict comes from Kane.

Zelkaro never decides a leak itself. It plants, reads Kane's own network capture, attacks, and asks Kane.

01PLANT

Kane signs in as the owner and saves a random canary in a private record.

02DISCOVER

Its network log reveals every page and API that touched the record.

03PROBE

Kane opens each route as a second user and logged out.

04TAMPER

As the second user, Kane tries to overwrite the record.

05CONTROL

Kane confirms the owner still sees it, untouched. "Deny everyone" fails.

What this does not prove

    
We'd rather be trusted than impressive.

    

      
      
The bugs in this run were planted in our demo. When we asked a fresh Claude Code session to build the same app with no hint about security, it did not write this bug, so we don't claim AI always ships it. Real leaks come from later edits, forgotten routes and database rules switched off in a dashboard. Zelkaro covers one record type and two accounts per config; probes open URLs directly, so bearer-token-only APIs need more work. Zelkaro doesn't predict leaks. It proves, from outside, that there aren't any, with the screenshots to show for it.
